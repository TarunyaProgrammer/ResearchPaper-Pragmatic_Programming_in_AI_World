\begin{abstract}
The rapid integration of Large Language Models (LLMs) and autonomous AI coding agents has initiated a fundamental transformation in software development. While traditional programming paradigms prioritized manual syntax construction and boilerplates, AI-assisted development shifts developer responsibilities toward high-level intent specification, architectural governance, and automated verification. This empirical study investigates how traditional software engineering principles—specifically orthogonality, duplication avoidance (DRY), modularity, and test-driven verification—manifest in software projects developed alongside AI coding agents. By analyzing classified repository change data and qualitative defect taxonomies, we evaluate the relationship between AI assistance, change propagation, and software maintainability. Our findings provide empirical insights into structuring effective human-AI pair programming workflows while mitigating architectural technical debt.
\end{abstract}

\textbf{Keywords---} Empirical Software Engineering, AI Coding Agents, Pragmatic Programming, Code Maintainability, Technical Debt, Repository Mining.

\section{Introduction}
Software development is undergoing a historic shift driven by AI-assisted coding tools and autonomous agents~\cite{githubcopilot2023}. Generative models, trained on vast codebases, act as interactive pair programmers, automated refactorers, and synthesis engines~\cite{pragmaticai2024}.

However, while AI tools accelerate initial code generation, they introduce novel software engineering challenges. Generative models operate probabilistically, occasionally hallucinating invalid APIs, introducing silent vulnerabilities, or generating verbose, non-idiomatic abstractions. Consequently, modern software engineers must adopt a \textit{pragmatic} approach: prioritizing empirical verification, architectural maintainability, and intent specification over uncritical acceptance of AI output.

This paper presents an empirical case study investigating how classic pragmatic software engineering principles manifest in AI-assisted software projects.

\section{Conceptual Framework: Pragmatic Principles as Measurable Metrics}
We operationalize qualitative principles from \textit{The Pragmatic Programmer} into observable quantitative software properties:
\begin{itemize}
    \item \textbf{Orthogonality:} Measured via \textit{Change Propagation Rate} (files and directory modules modified per commit).
    \item \textbf{DRY (Don't Repeat Yourself):} Measured via \textit{Code Duplication Ratio} across commit diffs.
    \item \textbf{Modularity:} Measured via \textit{Cyclomatic Complexity} and line churn per change.
    \item \textbf{Test Co-evolution:} Measured via the ratio of test line modifications to production code modifications.
\end{itemize}

\section{Related Work}
Existing research has extensively measured short-term developer productivity, task completion speeds, and snippet-level syntax accuracy. However, a significant gap remains regarding how AI assistance affects architectural health and change propagation over multi-commit repository lifecycles.

\section{Research Questions}
This study addresses four explicit Research Questions (RQs):
\begin{itemize}
    \item \textbf{RQ1:} How do traditional pragmatic software-engineering principles manifest in AI-assisted development?
    \item \textbf{RQ2:} How does AI-assisted code generation affect practices such as refactoring, testing, and modularity?
    \item \textbf{RQ3:} Which traditional engineering practices become more critical when implementation is delegated to AI agents?
    \item \textbf{RQ4:} What categories of engineering defects emerge when integrating AI-generated code into evolving systems?
\end{itemize}

\section{Methodology}
We conduct a mixed-methods empirical study combining quantitative repository mining with qualitative defect classification. Commits are categorized into AI-assisted ($N_{\text{AI}}$) versus human-only ($N_{\text{Human}}$) groups, followed by non-parametric statistical comparison (Mann-Whitney U) across change metrics.

\section{Results}
Our quantitative analysis evaluates differences in change propagation, test co-evolution, and refactoring frequency between AI-assisted and human-only development.

\section{Discussion \& Interpretation}
We interpret our empirical findings within the context of human-AI collaboration, highlighting pragmatic guardrails that preserve software maintainability.

\section{Threats to Validity}
We address threats to construct validity (proxy metric reliability), internal validity (developer experience confounders), and external validity (generalizability across languages).

\section{Conclusion}
Pragmatic programming in the AI era elevates the developer's role from code writer to intent architect and verification lead. Future work will expand our multi-repository telemetry pipeline across diverse open-source ecosystems.
